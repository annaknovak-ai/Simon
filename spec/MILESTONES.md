# MILESTONES.md — משחק Simon

מסמך זה מגדיר את אבני הדרך (Milestones) לפיתוח המשחק, על בסיס PRD.md, ARCHITECTURE.md ו-DESIGN.md. הפיתוח מחולק ל-Vertical Slices: כל Milestone מוסיף יכולת משתמש שלמה שעובדת מקצה לקצה. Milestone 0 הוא Milestone טכני להקמת הפרויקט והפריסה, ומהווה תנאי מקדים לכל השאר.

---

## Development Execution Rules — הנחיות ל-AI המבצע את הפיתוח

1. **סדר:** יש לפתח את ה-Milestones לפי הסדר שהוגדר במסמך זה, ללא דילוג.
2. **עצירה לאחר כל Milestone:** בסיום כל Milestone יש לעצור את הפיתוח ולהציג למשתמש:
   - מה מומש ומה התוצר הזמין.
   - תוצאות הבדיקות האוטומטיות.
   - סטטוס כל סעיף ב-Definition of Done (עבר / לא עבר), כולל מה שעל המשתמש לבדוק בעצמו ואיך.
   - הקישור לגרסה המפורסמת ב-GitHub Pages, החל מ-Milestone 0 — לאחר הדחיפה (ראו כלל 7).
3. **אישור מפורש:** אין להתחיל בפיתוח ה-Milestone הבא ללא אישור מפורש של המשתמש.
4. **היקף:** אין להוסיף פיצ'רים, מסכים או התנהגויות שאינם מוגדרים ב-PRD, ב-ARCHITECTURE או ב-DESIGN. במקרה של סתירה בין המקורות: ה-PRD קובע התנהגות, DESIGN.md קובע מראה, ARCHITECTURE.md קובע מימוש טכני. סתירה שלא נפתרה — יש לשאול את המשתמש ולא לנחש.
5. **משתמשת לא טכנית:** פעולות שהמשתמשת צריכה לבצע בעצמה (למשל ב-GitHub) יוסברו צעד אחר צעד, בשפה פשוטה.
6. **מצב עובד:** בסוף כל Milestone, הקוד בענף `main` נבנה, הבדיקות עוברות, והאתר המפורסם עובד.
7. **בדיקה מקומית לפני פרסום:** כל Milestone נבנה ונבדק קודם מקומית במחשב, לפי המחזור שב-CLAUDE.md. הפרסום ל-GitHub Pages קורה רק כשהמשתמשת מבקשת לדחוף ל-GitHub, וה-Workflow מפרסם אוטומטית. סעיפי Definition of Done שדורשים את האתר המפורסם או טלפון נבדקים אחרי הדחיפה. ב-Milestone 0, הבדיקה שהפריסה נעצרת כשבדיקה נכשלת דורשת דחיפות נוספות, ולכן תיעשה רק באישור המשתמשת.

**סביבות:** לפי ARCHITECTURE.md אין Database ואין Backend, ולכן אין סביבות Supabase או Database Migrations. יש שתי סביבות בלבד: Development (Vite Dev Server מקומי) ו-Production (GitHub Pages).

## Milestone 0 — הקמת הפרויקט ופריסה אוטומטית

**שם ומטרה:** להקים את שלד הפרויקט, את סביבת הפיתוח ואת תהליך הפרסום האוטומטי, כך שכל Milestone הבא יפורסם ויהיה ניתן לבדיקה בטלפון.

**מה יש לממש:**
- פרויקט Vite עם TypeScript, ללא UI Framework.
- Vitest מוגדר, עם בדיקה בסיסית אחת שעוברת.
- קובץ HTML עם `lang="he"` ו-`dir="rtl"`, ו-viewport למובייל.
- משתני CSS (Design tokens) לכל צבעי ה-Color Palette, הטיפוגרפיה, הפינות, הצללים והמרווחים מ-DESIGN.md, ורקע כהה.
- דף זמני בעברית עם הכותרת „סימון”.
- Git Repository ב-GitHub. **פעולת משתמשת בהדרכה צעד אחר צעד:** יצירת ה-Repository והגדרת מקור הפרסום של GitHub Pages ל-GitHub Actions.
- Workflow של GitHub Actions: Push ל-`main` או הפעלה ידנית ← `npm ci` ← בדיקות ← `npm run build` ← פרסום `dist` ל-GitHub Pages. הרשאות מינימליות וגרסאות Actions נעולות, לפי ARCHITECTURE.md §6.
- הגדרת `base` ב-Vite לפי שם ה-Repository.

**תוצר מצופה:** דף עברי בסיסי מתפרסם אוטומטית ב-GitHub Pages ונפתח בטלפון.

**Definition of Done:**
- [ ] `npm run dev` מציג את הדף מקומית.
- [ ] `npm test` ו-`npm run build` עוברים ללא שגיאות.
- [ ] Push ל-`main` מפעיל את ה-Workflow, והוא מסתיים בהצלחה.
- [ ] כשל בבדיקות עוצר את הפריסה (נבדק פעם אחת בבדיקה שנכשלת בכוונה, ולאחר מכן מוחזר).
- [ ] הדף זמין בכתובת GitHub Pages ב-HTTPS, ונפתח בטלפון Android וב-iPhone.
- [ ] הדף מוצג מימין לשמאל, ברקע כהה, עם הכותרת „סימון”.

## Milestone 1 — משחק שלם (ללא צלילים)

**שם ומטרה:** לאפשר לשחק משחק מלא מההתחלה ועד הסוף — התחלה, צפייה ברצף, שחזור, הצלחה, הפסד, ניצחון ומשחק חוזר. זהו לב המוצר.

**מה יש לממש:**
- **Game Engine** כמכונת מצבים: `idle`, `showing-sequence`, `player-turn`, `transition`, `game-over`, `won` (ARCHITECTURE.md §2.2). יצירת רצף אקראי, הוספת צבע אחד בכל שלב, עד 10 שלבים, וחישוב הניקוד.
- **מסך הבית** לפי DESIGN.md: כותרת, תג „שלב X מתוך 10”, „ניקוד”, לוח המשחק (ארבעה מקטעים בסידור הקבוע), כפתור „התחל”, והוראות משחק קצרות לפי ההחלטה שהתקבלה.
- **הצגת רצף:** הארת מקטע עם Glow, עמעום שאר המקטעים, טקסט „מקשיב לרצף...” ואייקון רמקול כחיווי.
- **תור השחקן:** טקסט „תור השחקן”, הארת מקטע בלחיצה, נעילת הלוח בכל מצב אחר.
- **מצבי סיום:** הצלחה („כל הכבוד!”), הפסד („ניסיון נכשל!” + „שחק שוב” אדום), ניצחון („סיימת את המשחק!” + „שחק שוב” כחול). בשלב זה „שיא אישי” במצב ניצחון מציג ערך זמני מתוך המשחק הנוכחי; החיבור לאחסון יתבצע ב-Milestone 3.
- רענון הדף מחזיר למצב `idle`.
- בדיקות Vitest ללוגיקת המשחק, לפי ARCHITECTURE.md §9 (ללא סעיפי האחסון).

**תוצר מצופה:** משחק Simon שניתן לשחק בו בטלפון מהאתר המפורסם, עם כל מצבי התצוגה, ללא צליל.

**Definition of Done:**
- [ ] בדיקות אוטומטיות עוברות עבור: אורך רצף והוספת צבע בכל שלב; התקדמות לאחר רצף נכון; סיום מיידי בטעות; נעילת קלט מחוץ ל-`player-turn`; ניקוד 0 בטעות בשלב 1 וניקוד 5 בטעות בשלב 6; ניצחון לאחר שלב 10 ללא שלב 11.
- [ ] בטלפון: „התחל” מציג רצף, והלחיצות במהלך הצגת הרצף ובמעבר בין שלבים אינן משפיעות.
- [ ] שחזור נכון מציג את מצב ההצלחה ועובר אוטומטית לשלב הבא עם צבע נוסף.
- [ ] טעות מציגה מיד את מצב ההפסד עם הניקוד הנכון; „שחק שוב” מתחיל משחק חדש.
- [ ] השלמת 10 שלבים מציגה את מצב הניצחון.
- [ ] רענון הדף באמצע משחק מחזיר למצב התחלה.
- [ ] כל הטקסטים בממשק בעברית, והמראה תואם ל-DESIGN.md ול-Mockups.
- [ ] הגרסה פורסמה ל-GitHub Pages ועובדת בטלפון.

## Milestone 2 — צלילים

**שם ומטרה:** להוסיף לכל צבע צליל ייחודי, כך שהשחקן ישמע את הרצף ואת הלחיצות שלו.

**מה יש לממש:**

- יצירה או חידוש של `AudioContext` בעקבות לחיצה על „התחל” או „שחק שוב”, לפני ניגון הרצף.

**תוצר מצופה:** המשחק המלא עם צלילים, עובד בטלפון.

**Definition of Done:**
- [ ] לכל אחד מארבעת הצבעים צליל שונה וניתן להבחנה.
- [ ] הצליל מתנגן בזמן הארת המקטע, בהצגת הרצף ובלחיצת השחקן.
- [ ] הצלילים פועלים לאחר לחיצה על „התחל” ב-Android וב-iPhone.
- [ ] אין בפרויקט קובצי שמע ואין בקשות רשת לצורך שמע.
- [ ] כל הבדיקות מ-Milestone 1 עדיין עוברות.

## Milestone 3 — שמירת ניקוד ומסך „אודות”

**שם ומטרה:** לשמור את התוצאה האחרונה ואת השיא האישי במכשיר, ולאפשר לצפות בהם במסך „אודות”.

**מה יש לממש:**
- **Score Storage:** קריאה וכתיבה של `simon.lastResult` ו-`simon.bestScore` ב-Local Storage, עם אימות שהערכים הם מספרים שלמים בטווח 0–10, טיפול בנתונים חסרים או פגומים, ותפיסת שגיאות גישה. אם האחסון אינו זמין — שימוש בערכים זמניים בזיכרון, בלי להציג כאילו הנתונים נשמרו.
- עדכון הניקוד בסיום משחק (הפסד או ניצחון) לפי כללי ARCHITECTURE.md §3.3.
- „שיא אישי” במצב ניצחון מוצג מתוך האחסון.
- **מסך „אודות”** לפי DESIGN.md: כותרת עם חץ חזרה, כרטיס „התוצאה האחרונה” (גביע) וכרטיס „השיא האישי” (כוכב), עם ערך התחלתי כשאין נתונים.
- **ניווט:** קישור „אודות” בתחתית מסך הבית, וחץ חזרה למסך הבית.
- בדיקות Vitest לאחסון ולכללי הניקוד.

**תוצר מצופה:** המוצר המלא בשני המסכים, עם שמירת ניקוד מקומית.

**Definition of Done:**
- [ ] בדיקות אוטומטיות עוברות עבור: עדכון התוצאה האחרונה; עדכון השיא רק כשהתוצאה גבוהה ממנו; ערכים חסרים, פגומים ומחוץ לטווח; Local Storage שאינו זמין.
- [ ] בטלפון: לאחר משחק, „אודות” מציג את התוצאה האחרונה והשיא הנכונים.
- [ ] הנתונים נשמרים לאחר סגירה ופתיחה מחדש של הדפדפן.
- [ ] רענון באמצע משחק אינו מעדכן את התוצאה האחרונה.
- [ ] בפעם הראשונה (ללא נתונים) מוצג ערך התחלתי ולא שגיאה.
- [ ] הניווט בין מסך הבית ל„אודות” ובחזרה עובד.
- [ ] כל הבדיקות הקודמות עוברות, והגרסה פורסמה ל-GitHub Pages.

## Milestone 4 — PWA ועבודה Offline

**שם ומטרה:** לאפשר התקנה של המשחק במכשיר ומשחק מלא ללא אינטרנט, לאחר טעינה ראשונה.

**מה יש לממש:**
- `vite-plugin-pwa` עם Workbox: Web App Manifest (שם בעברית, אייקונים, צבעים מה-Style Guide) ו-Service Worker.
- שמירה ב-Cache של כל משאבי האפליקציה, כולל HTML, JavaScript, CSS, אייקונים וקובצי הגופנים המקומיים.
- התאמת נתיבי Manifest, אייקונים ו-Service Worker לנתיב ה-`base` של GitHub Pages.
- מדיניות עדכון Cache שמונעת ערבוב קבצים מגרסאות שונות.
- אייקון אפליקציה פשוט של לוח המשחק, ש-Claude יוצר (DESIGN.md, החלטה 11).
- אין הוראות התקנה בתוך המשחק (DESIGN.md, החלטה 10). Claude מסביר למשתמשת בצ'אט איך להתקין ב-Android וב-iPhone.

**תוצר מצופה:** אפליקציה שניתן להתקין בטלפון ולשחק בה במצב טיסה.

**Definition of Done:**
- [ ] ה-Build מייצר Manifest ו-Service Worker תקינים.
- [ ] ב-Android (Chrome) המשחק ניתן להתקנה; ב-iPhone (Safari) ניתן להוסיף אותו למסך הבית.
- [ ] לאחר טעינה ראשונה והתקנה, במצב טיסה: המשחק נפתח, ניתן לשחק, הצלילים פועלים, הגופן מוצג נכון והניקוד נשמר.
- [ ] לאחר פרסום גרסה חדשה, האפליקציה המותקנת מתעדכנת ופועלת תקין, ללא תקלות של קבצים מעורבים.
- [ ] כל הבדיקות הקודמות עוברות, והגרסה פורסמה ל-GitHub Pages.
