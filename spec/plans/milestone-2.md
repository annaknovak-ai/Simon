# תוכנית Milestone 2 — צלילים

מקורות: MILESTONES.md (Milestone 2), PRD.md §3–4 (צליל ייחודי לכל צבע, הארה + צליל ברצף), ARCHITECTURE.md §1.2, §1.5, §2.2 (C. Audio Service), §4.1, §9, DESIGN.md (מסך 1א–1ב, החלטות 8–9), ADR-4.

## 1. מטרה והיקף

לכל אחד מארבעת הצבעים צליל משלו, שנוצר בקוד (Web Audio API). הצליל מתנגן יחד עם הארת המקטע — גם כשהמשחק מציג את הרצף וגם כשהשחקן לוחץ נכון.

**בתוך ההיקף:** Audio Service, הפעלת השמע בלחיצה על „התחל” / „שחק שוב”, סנכרון צליל והארה, בדיקות Vitest ל-Audio Service.

**מחוץ להיקף:**
- צליל טעות, צליל הצלחה או צליל ניצחון — לא מוגדרים במוצר (DESIGN, החלטה 9: „אין צליל טעות מיוחד”).
- כפתור השתקה או הגדרות עוצמה — לא במוצר (PRD §מחוץ להיקף, DESIGN: „אין במוצר השתקה”).
- אייקון הרמקול נשאר חיווי בלבד ולא הופך לכפתור.
- Local Storage ו„אודות” — Milestone 3. PWA — Milestone 4.

## 3. Audio Service (`src/audio/audioService.ts`)

### 3.1 הצלילים
ארבעה תווים במרחק ברור זה מזה, בהשראת משחק ה-Simon המקורי, בצורת גל `triangle` (רכה ונעימה, ונשמעת היטב ברמקול טלפון):

| צבע | תדר (Hz) |
|---|---|
| ירוק | 415 |
| אדום | 310 |
| צהוב | 252 |
| כחול | 209 |

הטבלה מיוצאת כקבוע `TONES: Record<Color, number>`, כדי שהבדיקות יוכלו לוודא שארבעת התדרים שונים.

### 3.2 ממשק
```ts
createAudioService(createContext?: () => AudioContext): AudioService
interface AudioService {
  unlock(): void;                        // called synchronously inside the Start / Play-again click
  play(color: Color, durationMs: number): void;
}
```
- `createContext` ניתן להזרקה (ברירת מחדל: `new AudioContext()`, או `webkitAudioContext` בדפדפנים ישנים) — כדי לבדוק בלי דפדפן.
- **`unlock()`:** בפעם הראשונה יוצר את ה-`AudioContext`. בכל קריאה, אם המצב אינו `running` (`suspended`, או `interrupted` ב-iPhone) — קורא ל-`resume()`. בפעם הראשונה מנגן גם צליל שקט וקצרצר, כדי ש-Safari ב-iPhone „ישחרר” את השמע בתוך הלחיצה.
- **`play(color, durationMs)`:** יוצר `OscillatorNode` + `GainNode` חדשים לכל צליל, מתחיל ב-`currentTime` (מיידית, באותו רגע שבו המקטע נדלק), ועוצר אחרי `durationMs`.
  - **מעטפת עוצמה** למניעת „קליקים”: עלייה של ~10ms לעוצמה ~0.3, ודעיכה של ~40ms לפני הסוף.
  - לכל צליל משלו — שני צלילים חופפים (למשל לחיצות מהירות) לא מפריעים זה לזה.
- **עמידות:** אם הדפדפן לא תומך ב-Web Audio, אם יצירת ה-Context נכשלת, או אם `play` נקרא לפני `unlock` — הפונקציות לא עושות כלום ולא זורקות שגיאה. המשחק ממשיך לעבוד בלי צליל. כל קריאה ל-`resume()` עטופה כך ששגיאה בה לא תפיל את המשחק.

## 4. חיבור לבקר המסך (`src/ui/homeScreen.ts`)

- יצירת `const audio = createAudioService()` פעם אחת ב-`mountHomeScreen`.
- **`startGame()`** (משמש גם „התחל” וגם „שחק שוב”): הקריאה הראשונה בפונקציה היא `audio.unlock()` — עדיין בתוך הלחיצה, לפני ניגון הרצף (ARCHITECTURE §4.1 שלב 2).
- **הצגת רצף** (`playSequence`): מיד אחרי `board.light(color)` ← `audio.play(color, SEQUENCE_LIT)`. משך הצליל = משך ההארה (0.5 שנייה).
- **לחיצה נכונה** (`handlePress`, תוצאות `correct` / `level-complete` / `won`): מיד אחרי `board.light(color)` ← `audio.play(color, PRESS_LIT)` (0.25 שנייה).
- **לחיצה שגויה:** בלי צליל — רק ההבהוב הקיים (DESIGN, החלטה 9; ARCHITECTURE §2.2: צליל רק ב„לחיצה תקפה”).
- **לחיצה נעולה** (`ignored`): בלי צליל ובלי הארה — כמו היום.
- התזמונים הקיימים לא משתנים. טיימר ממשחק קודם (`runId`) כבר לא מגיע ל-`light`, ולכן גם לא מנגן צליל.

## 5. התנהגות במכשירים

- **Android (Chrome) ו-iPhone (Safari):** השמע מתחיל רק אחרי לחיצה של המשתמשת — וזו בדיוק הלחיצה על „התחל”.
- **חזרה לאפליקציה אחרי מעבר לאפליקציה אחרת / נעילת מסך:** הדפדפן עלול להשהות את השמע. הלחיצה הבאה על „שחק שוב” מפעילה אותו מחדש. (באמצע משחק — אם השמע הושהה, `play` לא יישמע עד ה„התחל” הבא; המשחק עצמו לא נפגע.)
- **iPhone במצב שקט (מתג הצד):** Safari משתיק צלילי Web Audio כשהטלפון במצב שקט. זו התנהגות של המכשיר, לא באג — בבדיקה יש לוודא שהמתג על „צלצול” והעוצמה מורמת.

## 6. בדיקות (`tests/audio.test.ts`)

הבדיקות רצות בסביבת `node` עם `AudioContext` מדומה פשוט (אובייקט שמתעד אילו oscillators נוצרו, באיזה תדר, ומתי התחילו ונעצרו):
1. ארבעת התדרים ב-`TONES` שונים זה מזה, ולכל צבע יש תדר.
2. `play` לפני `unlock` — לא יוצר צליל ולא זורק שגיאה.
3. אחרי `unlock`, `play('green', 500)` יוצר oscillator בתדר של ירוק, שמתחיל עכשיו ונעצר אחרי 0.5 שנייה.
4. `unlock` כשה-Context במצב `suspended` קורא ל-`resume()`; כשהוא `running` — לא.
5. `unlock` יוצר Context אחד בלבד גם אם נקרא כמה פעמים.
6. כשיצירת ה-Context זורקת שגיאה (אין תמיכה) — `unlock` ו-`play` לא זורקים.

כל בדיקות Milestone 1 (`engine.test.ts`, `appInfo.test.ts`) ממשיכות לעבור ללא שינוי.

**בדיקה ידנית בבנייה (שלי):** הרצת `npm run dev`, משחק בדפדפן, ובדיקה בלשונית ה-Network שאין בקשות לקובצי שמע. בדיקה שבתיקיית הפרויקט וב-`dist` אין קבצים כמו `.mp3` / `.wav` / `.ogg`.

## 7. ADR להוספה ב-ARCHITECTURE.md

**ADR-6: Audio Service עם צלילים שנוצרים בקוד**
- **הקשר:** §2.2 (C) דורש ארבעה צלילים ב-Web Audio API, בלי קובצי שמע, ושהשמע יופעל בלחיצת „התחל” בגלל מדיניות הדפדפנים.
- **החלטה:** `src/audio/audioService.ts` יוצר `AudioContext` יחיד בלחיצה הראשונה על „התחל” ומפעיל אותו מחדש בכל „התחל” / „שחק שוב”. כל צליל הוא oscillator מסוג `triangle` עם מעטפת עוצמה קצרה. התדרים: ירוק 415, אדום 310, צהוב 252, כחול 209 Hz. בקר המסך מנגן צליל באותן נקודות שבהן הוא מאיר מקטע, באותו משך. בלחיצה שגויה אין צליל.
- **השלכות:** אין קובצי שמע ואין בקשות רשת לשמע, ולכן ב-Milestone 4 אין מה להוסיף ל-Cache בשביל צלילים. אם השמע לא זמין, המשחק עובד בשקט. ב-iPhone במצב שקט לא יישמע צליל.

## 8. סדר עבודה

1. `src/audio/audioService.ts` + `tests/audio.test.ts` ← `npm test`.
2. חיבור ב-`homeScreen.ts`.
3. `npm test`, `npm run build`.
4. הרצת `npm run dev` ומשחק בדפדפן: צליל שונה לכל צבע, צליל בהצגת הרצף ובלחיצה נכונה, אין צליל בלחיצה שגויה או נעולה, „שחק שוב” ממשיך לנגן. בדיקת Network ותיקיות (סעיף 6). סגירת ההרצה.
5. ADR-6 ב-ARCHITECTURE.md, 🟡 ב-MILESTONES.md.
